# 手册曲线数字化工具

这个工具把柯达技术手册（PDF）里的曲线读成数据，写成数据库能读的参考曲线 CSV。它服务于 D1 阶段：D1 要用厂商手册里的曲线标定胶片和显影液的机理模型，所以每条曲线都得能追溯到具体的出版物、版次、页码和图名，并且能一键复现。

工具读的是 PDF 里的矢量路径，不靠人眼描点。2016–2021 年版的 F-4017 里，每条曲线都是一条矢量路径。工具读出它的坐标，再用坐标轴上的刻度换算成数据。

## 准备

需要 [uv](https://docs.astral.sh/uv/)。PDF 解析库放在单独的 `digitize` 依赖组里，不进运行时依赖：

```bash
uv sync --group digitize
```

用到的库：pdfminer.six 读路径和文字，pypdfium2 把页面渲染成图片，pdfplumber 只用来查看文字。不用 PyMuPDF（AGPL 许可）。

## 安全约定

- PDF 只放在 `.cache/datasheets/pdf/`。这个目录被 git 忽略，PDF 永不提交。
- 只从柯达自己的站点下载：kodak.com、kodakalaris.com、imaging.kodakalaris.com、kodakprofessional.com、business.kodakmoments.com，以及 web.archive.org 上这些站点的存档。`fetch` 命令会检查网址和 sha256，不符合就拒绝。
- PDF 是不可信输入，只解析不执行。所有读 PDF 的命令都用 `python -I` 运行。`-I` 不把当前目录放进模块搜索路径；工具之所以仍能 `-m tools.digitize`，是因为 `pyproject.toml` 让开发安装把仓库根目录放进了搜索路径（`dev-mode-dirs`）。

## 一键复现

```bash
uv run --group digitize python -I -m tools.digitize fetch   # 按配方下载 PDF，校验 sha256
uv run --group digitize python -I -m tools.digitize run     # 跑全部配方，写 CSV 和核对图
uv run --group digitize python -I -m tools.digitize check   # 重跑并逐字节比对已暂存的 CSV
```

`check` 不写文件。只要有一个 CSV 和配方的结果不一致，或者某个版本交叉校验超差，它就以状态 1 退出。

## 命令

所有命令的前缀都是 `uv run --group digitize python -I -m tools.digitize`。

| 命令 | 作用 |
|------|------|
| `paths PDF 页 [--region x0,y0,x1,y1] [--all]` | 列出页面上的矢量路径：序号、线宽、虚线数组、颜色、算子序列、外框 |
| `text PDF 页 [--region ...]` | 列出单词和外框；带横杠记号的刻度标注会标 `[bar]` |
| `images PDF 页` | 列出嵌入的位图。图是位图时要改用光栅模式 |
| `render PDF 页 输出.png [--scale 4] [--region ...]` | 把整页或一个区域渲染成 PNG |
| `run [配方 ...]` | 跑配方（不给就跑全部），写暂存 CSV 和核对图，打印摘要 |
| `check [配方 ...]` | 在内存里重跑，和暂存的 CSV 逐字节比对 |
| `fetch [配方 ...]` | 下载配方用到的 PDF |

坐标一律是 PDF 页面坐标，单位为点（1/72 英寸），原点在页面左下角，y 向上。`paths` 和 `text` 打印的就是这种坐标，配方里也直接用它。

## 目录

```
tools/digitize/                       工具本身（Python 包）
tools/digitize/recipes/<出版物>-<版次>/<图>.yaml   每张图一个配方
tools/digitize/staged/<材料>/<名字>.csv            数字化结果（暂存）
tools/digitize/staged/<材料>/tables.yaml           表格和单个数值
.cache/datasheets/pdf/                PDF（不提交）
.cache/datasheets/overlays/<材料>/    核对图（不提交）
```

结果先放在 `staged/`，没有直接进 `data/reference/`。原因是胶片数据文件还不存在，而数据库会拒绝没有对应材料的参考曲线。以后由别的任务把它们移过去。

## 配方怎么写

一个配方描述一张图，所有判断都写在文件里，换个人重跑也得到同样的结果。字段如下：

- `publication`：出版商、编号、标题、版次、网址、PDF 文件名和 sha256。运行前会校验 sha256。
- `page`：PDF 文件里的页序（从 1 起）。`printed_page` 是印在页面上的页码。
- `figure`、`caption`：图名和图里印的工艺说明，照原文抄。
- `region`：图所在的区域。`frame`：坐标框（一个描边矩形，从 `paths` 的输出里取）。`exclude`：图例框之类的区域，里面的路径不会当成曲线。
- `x`、`y`：两条坐标轴的标定，见下一节。
- `curves`：每条输出曲线一项，写明输出文件名、物理量、图例文字、线型（线宽和虚线数组）、显影条件，以及对结果的检查（`expect`）。
- `flatten_tolerance_pt`：贝塞尔曲线展平的容差（点），默认 0.01。
- `decimals`：输出保留的小数位，默认 x、y 都是 4 位。

### 坐标轴标定

每条轴至少用两个参考点，通常是所有带数字的刻度。配方给出刻度上印的文字（`label`）和它代表的数值（`value`），工具做两件事：

1. 在坐标框外侧的标注带里找到这段文字。
2. 找离它最近的刻度线、网格线或坐标框边，取它的位置。两条候选线离得差不多近时报错，要求手工给坐标。

`scale` 取 `linear` 或 `log10`。`fit` 取 `lsq`（对所有参考点做最小二乘直线）或 `piecewise`（在相邻参考点之间分段线性，正好穿过每个刻度）。印刷网格本身不均匀时用 `piecewise`，比如 F-4017 的 MTF 图，各个十倍程的长度相差约 1.5 点。无论用哪种，工具都报告最小二乘残差，并把它计入误差。

柯达把负对数印成横杠记号：数字 3 上面加一道横杠表示 −3。横杠是一条短路径，不是字符，所以文字层只读出 "3.0"。配方里写 `bar: true` 的标注，工具会检查上面确实有横杠；写成没有横杠的标注，上面就必须没有。数值始终以配方为准，工具不从文字推断正负。

只有在实在没有可用标注时，才用 `coord` 直接给坐标，同时必须用 `note` 说明是从哪里读的。

### 选曲线

同一张图里的曲线靠线宽和虚线数组区分（例如 6 分钟实线，11 分钟长短划线）。配方的 `style` 写出线宽和虚线数组，工具在坐标框内找符合的路径。框线、刻度、网格线和图例样线都只由水平或竖直线段组成，会被自动排除。

`legend` 写图例文字时，工具会找到文字左边的样线，核对它的线型和 `style` 一致。不一致就报错。这样可以防止把两条线型相近的曲线对调，比如对比度指数图里，D-76 (1:1) 和 HC-110 (B) 的虚线数组相同，只有线宽不同（0.432 点和 0.72 点）。

`expect` 写检查项：应当匹配几条路径，曲线首尾的 x（`x_span`）大致是多少。不满足就报错。

### 路径怎么变成数据

1. 每条路径按子路径展平成折线。直线段保留端点，贝塞尔曲线反复二分，直到控制点离弦的距离都不超过容差。
2. 用两条轴的标定把点换算成数据。
3. 每段折线调成从左到右，几段按起点排序后接起来，四舍五入到 `decimals` 位。
4. 只保留 x 严格递增的点。完全重复的点和舍入后 x 相同的点直接丢弃，摘要里给出计数。x 往回走的点，在 `monotonic: strict`（默认）下报错；改成 `drop-backtracking` 时丢弃并计数，但必须在 `monotonic_reason` 里写明原因。

工具不做平滑，不插值，不重采样。输出的点就是路径上的顶点（或展平得到的点）。

### 误差估计

每条曲线的误差写在 CSV 的 `ref` 里，x、y 分开给。算法是：

- 矢量路径：（线宽 + 展平容差）换算到数据单位，加上该轴最小二乘残差的最大值。
- 对数轴上的误差以十倍程计，同时给出相应的百分比。

路径的中心线本身是精确的，所以把整条线宽算进误差偏保守。线宽代表这张图能表达的精度。

### 光栅回退

如果图是嵌入的位图（`images` 能列出来），用 `method: raster`。工具按 `raster_dpi` 渲染页面，把暗于阈值的像素当作墨迹，从配方给的种子点出发逐列追踪，可以跨过虚线的空隙。刻度标定方法不变；没有文字层时就用 `coord` 手工给。

这种曲线的 `ref` 会写明是从光栅追踪的，误差取墨迹列高的中位数加一个像素，比矢量路径大得多。本次数字化的 Tri-X 图全是矢量，没有用到光栅模式；它只有单元测试覆盖。

## 输出格式

CSV 是数据库的参考曲线格式：先是若干行 `# 键: 值`，然后是没有表头的 `x,y` 数据行。

- `material`：`kodak/tri-x-400` 这样的材料 id。
- `quantity`：物理量，比如 `characteristic_curve`、`contrast_index`、`modulation_transfer`、`spectral_sensitivity`。
- `x_unit`、`y_unit`：照图上印的单位，比如 `log10(lux*s)`、`min`、`cycles/mm`、`%`、`nm`、`log10(cm2/erg)`。密度、对比度指数这类无量纲量写 `1`。
- `origin`：固定为 `datasheet`。
- `ref`：完整出处，包括出版商、标题、编号、版次、页码、图名、哪条曲线、网址、sha256、配方路径和误差估计。
- `conditions`：显影条件，写成 `键=值; 键=值`。用到的键有 developer（`d-76`、`xtol`、`hc-110`、`t-max-dev`、`t-max-rs`）、dilution、time、temperature、agitation、format、densitometry、exposure。图上没写的条件就写"not stated"，不去猜。

`tables.yaml` 放表格和单个数值：互易律修正、各显影液各温度各罐型的显影时间、增感冲洗、RMS 颗粒度、片基、灰雾、曝光指数等。每一块都写明来源（`sources` 里的键）、印刷页码和表名。时间同时保留印刷原样（"6¾"、"NR"、"—"）和十进制分钟数。NR（不推荐）和 "—"（没给时间）记为 null，不当成数字。

这些表格不是配方生成的。它们取自 PDF 文字层（6¾ 在文字层里是 "63⁄4"），再逐格对照渲染页面核对。

## 已完成的数字化：Tri-X 400（400TX）

来源是 F-4017，2021 年 10 月版（Revised 10-21）。

| 配方 | 页 | 内容 | 输出 |
|------|----|------|------|
| `p8-char-tmax-dev-35mm` | 8 | 特性曲线，T-MAX 显影液，小罐 30 秒间隔搅动，20 °C，35 mm | 6、7、9、11 分钟 |
| `p8-char-tmax-dev-120` | 8 | 同上，120 | 6、7、9、11 分钟 |
| `p9-char-d76-35mm` | 9 | 特性曲线，D-76，大罐 1 分钟间隔搅动，20 °C，35 mm | 6、8、10、12 分钟 |
| `p9-char-d76-120` | 9 | 同上，120 | 6、8、10、12 分钟 |
| `p9-contrast-index-small-tank` | 9 | 对比度指数与显影时间，小罐，20 °C | D-76、D-76 1:1、XTOL、XTOL 1:1、HC-110 (B)、T-MAX、T-MAX RS |
| `p8-mtf` | 8 | 调制传递函数，D-76 大罐 | 1 条 |
| `p8-spectral-sensitivity` | 8 | 光谱感光度，等效曝光 0.5 秒 | D=0.3 和 D=1.0（高于灰雾） |

各条曲线的误差估计：

- 特性曲线：log H 约 ±0.020，密度约 ±0.016。
- 对比度指数曲线：时间 ±0.07 分钟（HC-110 那条线更粗，±0.12），CI ±0.003（HC-110 ±0.005）。
- MTF：两个轴都约 ±0.02 个十倍程（约 5%）。
- 光谱感光度：波长 ±1.8 nm，对数感光度 ±0.02。

### 版本交叉校验

`recipes/f4017-2016-02/` 和 `recipes/f4017-2007-05/` 是交叉校验配方。它们用同样的方法读旧版里的同一张图，不写文件，只把结果和 2021 年版暂存的曲线比较，差值必须在 `max_difference` 以内。

- 2016 年 2 月版（第 7、8 页）：7 张图全部一致，差别只在第 4 位小数的舍入。路径就是 2021 年版的路径挪了位置。
- 2007 年 5 月版（第 10–12 页，柯达官网的 Wayback 存档）：4 张特性曲线图和 MTF、光谱图都在 0.005 以内。这一版的曲线是另画的折线，6 分钟实线差得最多（0.0023 D）。2007 年版的对比度指数图线型不同，没有做交叉校验。

所以 2016 年以来各版 400TX 的 T-MAX 和 D-76 特性曲线是同一组数据，2007 年版的数据也与之一致。

### 要注意的地方

- **光谱感光度的图例可能印反了。** 图例把下面那条虚线标为 D=0.3，把上面那条实线标为 D=1.0。可是达到更低的密度需要的曝光更少，对数感光度应该更高，所以 D=0.3 应该是上面那条。文件按印刷的图例命名，`conditions` 里加了 `legend_check` 提醒，用的人自己判断。
- **MTF 和光谱感光度用的是老乳剂。** 2007 年版第 10 页说这两张图是用老的 TRI-X Pan（5063）做的，颗粒度数据也是旧版胶片的。后来的版本删了这句话，但图没变。
- **没有 XTOL 和 HC-110 的 400TX 特性曲线。** 第 9–10 页 HC-110 (B) 和 D-76 的特性曲线标的是 TRI-X 320 / 320TXP 页片，是另一种胶片，没有数字化。第 10 页三张对比度指数图（大罐、盘、转筒）也都是 320TXP 的。
- 400TX 的对比度指数图只有小罐一种，图上也没写搅动间隔。
- 特性曲线没写曝光光源和曝光时间。2007 年版 MTF 图的曝光一栏只印了 "Exposure: X"。
- 400TX 的片基、片基加灰雾在三个版本里都没有给出。`tables.yaml` 记的是 null，另外列出了各条特性曲线左端（log H = −3.45）的密度，作为片基加灰雾的上限，不是测量值。
- 转筒冲洗的普通表和增感表，与小罐的表逐格相同。照原样记录。

### 没有数字化的

- 第 2 页的互易律曲线图：两张图叠在一起，右侧有分钟和秒两套刻度，没有可靠的单一标定。表格部分（1、10、100 秒等）已经在 `tables.yaml` 里。
- 2007 年版第 11 页的 VERSAMAT 11 / DURAFLO RT 特性曲线：这种显影液不在 D1 范围内。
- J-109 除表 1 以外的 400TX 行（转筒、大罐等）没有抄录。

## 测试

```bash
uv run pytest tests/tools                     # 不需要 PDF 库的部分
uv run --group digitize pytest tests/tools    # 加上用内存里手写的小 PDF 跑的那一项
```

测试不依赖下载的 PDF。它们用手工构造的路径和字符拼出一张图，检查以下几项：

- 贝塞尔展平的容差。
- 线性轴和对数轴的标定、最小二乘残差和分段标定。
- 横杠记号的识别、图例核对和曲线排序规则。
- CSV 能被数据库读回，且重跑结果逐字节相同。
- 光栅追踪。
- 下载网址的白名单。
